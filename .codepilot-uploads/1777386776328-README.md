# AI 阅读材料

这个目录给后续独立 AI/Codex session 阅读，不是正式产品文档，也不是用户侧运维手册。

阅读顺序：

1. `phase2-background-and-backend-architecture.md`
2. `prompt-versioning-and-ab-testing.md`
3. `v2-operations-lessons-for-v3.md`
4. `phase2-design-review-and-core-development-plan.md`
5. `next-session-brief.md`

核心结论：

- V3 prompt 必须支持版本更替、并跑测试和随时切换。
- 筛选标准与信息提取格式是两个独立 prompt 角色，不要绑死在同一个文件。
- V2 legacy prompt 已作为 baseline 放入 `prompts/versions/v2_legacy/`，内容用于对照，不作为 V3 默认生产逻辑。
- 第二阶段目标是完整后端 dry-run/staging 链路；live 定时任务、Obsidian 写入、Telegram 推送必须在 Runtime Guard、临时队列、dry-run、staging 验证之后再启用。
- Phase 2 后端应保持轻量：输入层、fetcher/skill 适配层、pipeline、output ports 分离；active bundle 写输出，parallel bundles 只做对照评估。
